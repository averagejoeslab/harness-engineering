The one idea

A model only predicts the next token. The harness is everything that turns that into an agent.

harness engineering · opening

If people remember one thing, it's this. The model is the mind; the harness is the body. Harness engineering is the practice of building that body.

The agent loop

Observe → think → act, and repeat

ObserveThinkAct
the dark, a floor, silencewhere am I? find outreach out
something flat and coola wall, so a room: find a switchslide your hand along it
smooth, smooth, then a small edgethat's a switchflip it

Light. Now you can see where you are, and the loop repeats with whatever you notice next. Every turn started from what the last one taught you.

harness engineering · what is an agent?

Three turns of the loop. Notice the goal changed as it learned: find out where I am, then find a switch. And each turn starts from what the last one taught you. Acting can also mean waiting and watching.

Agent = Harness(Model)

The model: the mind

Does the thinking. Tokens go in, and it predicts the next one.

The harness: the body

Captures input, assembles context, calls the model, handles its output, and defines the loop.

A model alone is a brain in a jar. A harness alone is a body without a head.

harness engineering · agent primitives

The core equation. Neither part is an agent alone: the model can only think, and the harness has nothing to decide what to do. Together they close the loop.

harness engineering · agent primitives

Five primitives. Every agent you've used, from a coding assistant to a chatbot that books flights, is a model inside these five. They differ only in how each primitive is built.

Trimmed, but real. It tried every test runner at once, read the code, spotted the flat discount, fixed it, and re-ran the tests. One run in between failed because pytest wasn't in its Python; it recovered on its own. This is the moment: it's an agent now.

harness engineering · production

These aren't new primitives. They're questions you ask of each of the five. Every line they add is marked in the code with the question it answers.

Safety & Security

What could do harm, and who could make it?

Safety

Guardrails against the agent's own mistakes: a box that sees only this folder, no network, and nothing runs without your yes.

Security

Guardrails against someone turning it against you: text it reads, secrets in its folder, a poisoned memory, a tampered image.

Both are guardrails, for different purposes. The guards that matter sit in the harness, where no text can talk them out of their job.

harness engineering · production · safety & security

One concern, two halves. Safety assumes a well-meaning agent that can still make mistakes. Security assumes an adversary who can put text in front of it.
